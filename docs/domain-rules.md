# 磨小二进销存系统领域规则

## 总则

规则以 [需求规格](requirements.md) 为范围基线。所有库存、金额、状态变化均由 Django 后端服务在单一数据库事务中执行；前端不得成为规则的最终裁决者。

## 术语与口径

| 术语 | 口径 |
| --- | --- |
| 库存余额 | 某 boss 的某商品当前可销售数量；首期没有仓库维度。 |
| 可用库存 | 首期等同库存余额；不支持锁定库存、在途库存。 |
| 库存流水 | 每次受控变动的一条不可变审计记录；数量增为正、减为负。 |
| 成本/毛利 | 商品维护两位小数进货价；销售与独立销售退货在完成时锁定单位成本，成本金额保留六位小数，毛利为净销售额减净销售成本。 |

## 库存规则

| 编号 | 规则 |
| --- | --- |
| INV-001 | 只能由初始库存、完成进货、完成销售、完成进货退货、完成销售退货改变库存；普通 CRUD 不得修改余额。 |
| INV-002 | 每次变动必须同时写入库存流水，记录组织、商品、来源类型及编号、变动数量、发生时间和操作人。 |
| INV-003 | 库存余额是查询投影，库存流水是权威审计来源；两者必须在同一事务中更新，余额可由流水汇总核验。 |
| INV-004 | 商品初始库存只能在首次建档时以 `INITIAL` 流水创建；后续纠正策略待确认，不能直接改余额。 |
| INV-005 | 销售、退货明细的商品必须属于当前 boss 数据空间。 |
| INV-006 | 销售完成禁止负库存；服务在事务内锁定余额后，任一商品库存不足时返回 `409 insufficient_stock`，且单据、余额和流水全部回滚。 |

## 单据状态机

首期单据采用草稿与已完成两种状态；作废和反审核仍不在首期范围。

| 类型 | 候选状态 | 允许转换 | 库存/金额影响 |
| --- | --- | --- |
| 采购、销售及两类退货 | `DRAFT` | `DRAFT -> COMPLETED` | 完成动作一次性生成对应流水。 |
| 上述单据 | `COMPLETED` | 无（首期） | 不得普通编辑或删除；纠错通过新建退货单。 |

| 编号 | 规则 |
| --- | --- |
| DOC-001 | 草稿可编辑；完成单据不可直接编辑、删除或以 PATCH 改状态。 |
| DOC-002 | 完成必须由专用动作触发，动作重复提交不得重复写流水或余额。 |
| DOC-003 | 单据明细、总额、完成人和完成时间均应保留审计追溯。 |
| DOC-004 | 作废、反审核及退货是否必须关联原单待确认；确认前不得发布对应动作接口。 |
| DOC-005 | 新建销售单、销售退货单、进货单、进货退货单分别使用 `SO`、`SR`、`PO`、`PR` 加 14 位 `YYYYMMDDHHmmss` 编号。时间取首次保存草稿时的服务器时间并显式转为北京时间 `Asia/Shanghai`，与业务日期无关，不改变 UTC 存储。 |
| DOC-006 | 同组织同类单据同一秒第一张无后缀，重号时依次追加 `-02`、`-03` 等序号，超过两位时继续使用 `-100` 等序号；依赖数据库唯一约束及事务保存点重试保证并发安全，不生成部分单据，其他约束异常正常抛出。 |
| DOC-007 | 新规则仅用于新建单据，不迁移或重写历史单号；编辑、完成和重放完成动作均不重新编号，内部 UUID、原单关联及库存规则保持不变。 |

## 金额规则

| 编号 | 规则 |
| --- | --- |
| MONEY-001 | PostgreSQL 使用 `numeric`，Python 使用 `Decimal`，JSON 中金额和高精度数量使用字符串，禁止 `float`。 |
| MONEY-002 | 单据行金额与单据总额必须由后端计算，客户端不可提交最终总额。 |
| MONEY-003 | 数量使用 `numeric(18,4)`，单价、行金额与总额使用 `numeric(18,2)`；行金额和总额按 `ROUND_HALF_UP` 量化。首期不支持折扣、税额或含税口径。 |
| MONEY-004 | 采购、销售、退货金额应由已完成单据聚合统计；销售退货须冲减销售金额。 |

## 基础资料规则

| 编号 | 规则 |
| --- | --- |
| MD-001 | 商品、规格、单位、属性、价格等级、客户、供应商均按 boss 隔离。 |
| MD-002 | 已被业务单据引用的基础资料不得物理删除；使用停用使其不可在新单据中选择，历史仍可查看。 |
| MD-003 | 价格等级默认零售价、批发价；同一组织最多六个有效等级。 |
| MD-004 | 规格预置尺码（S、M、L、XL、XXL）与颜色，单位预置常用单位；预置数据须明确归属与可否修改。 |
| MD-005 | 客户允许同名；仅同组织内名称、联系人、电话全部相同才算重复。供应商允许同名；仅同组织内名称、联系人、联系地址、电话全部相同才算重复。新增和修改均适用，修改排除自身并结合未修改字段判断。 |
| MD-006 | 重复检查包含已停用资料；可选联系字段仍可为空，空白值参与比较，备注和启停状态不属于身份字段。比较时忽略字段首尾空格，不忽略中间空格、大小写、电话号码标点或区号差异；不得模糊合并记录。 |
| MD-007 | 重复保存返回带中文说明的 409，停用资料冲突明确提示切换“仅停用”查看。数据库组合唯一索引防止并发写入重复资料；其他约束或服务器异常不得误报为重复。历史 UUID、字段原值、单据关联和库存数据不得因迁移改变。 |

## 权限规则

| 编号 | 规则 |
| --- | --- |
| AUTH-001 | 只有 boss 可注册；employee 仅能由所属 boss 创建，且只可访问所属 boss 的数据。 |
| AUTH-002 | boss 拥有其组织所有功能权限；employee 默认销售开单、进货开单和查询权限。 |
| AUTH-003 | 其他 employee 权限须由所属 boss 授予或审批申请；后端按功能及对象所属组织双重校验。 |
| AUTH-004 | 前端仅据权限隐藏入口或禁用操作，后端必须拒绝未经授权、未认证和跨组织操作。 |
| AUTH-005 | 店铺信息归 boss 组织；employee 是否可读或编辑待确认。 |

## 并发与一致性规则

| 编号 | 规则 |
| --- | --- |
| CON-001 | 完成单据时在事务内锁定对应库存余额行，检查前置条件、更新余额、写流水、更新单据状态和审计字段。任一步失败必须回滚。 |
| CON-002 | 同一动作使用服务端幂等键或等价唯一动作记录；相同请求重试返回首次成功结果，不重复出入库。 |
| CON-003 | 对不存在的库存余额行采用唯一约束与重试/锁定策略，避免并发创建重复余额。 |

## 审计与追溯

| 编号 | 规则 |
| --- | --- |
| AUD-001 | 业务单据、库存流水、权限授予和权限申请须记录操作者与时间。 |
| AUD-002 | 库存流水的来源、数量和操作信息不可被普通用户修改或删除。 |
| AUD-003 | 所有业务查询必须以组织过滤为默认条件，不能接受可绕过当前身份的组织标识。 |

## 成本与毛利规则

- 商品进货价必须非负；修改商品进货价只影响之后完成的销售或销售退货，不追溯已完成单据。
- 销售和销售退货在完成事务内锁定商品进货价并写入明细成本快照；退货因暂未关联原销售明细，使用退货完成时的进货价。
- 销售统计的净成本为完成销售成本减完成销售退货成本，毛利为净销售额减净成本。

## 待确认事项

- 后续确认作废/反审核路径时，必须先定义反向库存流水和审计规则。
- 后续如需先进先出、移动加权平均或销售退货关联原单成本，须在 RQ-06 的既有快照规则基础上定义迁移策略。
- 确认退货是否强制关联原进货/销售单，以及初始库存纠错方式（RQ-07）。
