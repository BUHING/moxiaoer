# 磨小二进销存系统需求规格

## 1. 目标

磨小二进销存系统（以下简称“系统”）面向小型零售或批发组织，在单台 Windows 电脑的浏览器中优先使用，后续可部署到局域网。首期提供按 boss 数据隔离的商品、购销、退货、库存查询、统计及员工授权能力，确保库存变动可追溯。

## 2. 范围

### 2.1 首期必须实现

| 模块 | 功能与业务结果 |
| --- | --- |
| 认证与账号 | 用户名、密码注册仅创建 boss；boss 与 employee 均可使用用户名、密码登录；JWT 会话。 |
| 员工与角色权限 | boss 创建所属 employee、查看并授予非默认权限；employee 可申请权限，由所属 boss 审批。employee 默认拥有销售开单、进货开单和所有已纳入模块的查询权限。 |
| 店铺信息 | 维护本 boss 的店铺信息。 |
| 商品 | 商品、规格、单位、商品属性、商品价格的创建、查询、修改、删除或停用；规格预置尺码与颜色，单位预置常用单位。商品建档可录入初始库存、进货价、规格、单位、属性及销售价格。 |
| 客户与价格等级 | 客户资料管理；默认零售价、批发价，最多六种价格等级，供商品定价与销售选择。 |
| 供应商 | 供应商资料管理，供进货选择。 |
| 进货与进货退货 | 进货单、进货退货单的录入、查询、修改与受控完成；完成进货增加库存，完成进货退货减少库存。 |
| 销售与销售退货 | 销售单、销售退货单的录入、查询、修改与受控完成；完成时锁定商品进货价为明细成本快照。完成销售减少库存并计入销售数据，完成销售退货增加库存并冲减销售金额与成本。 |
| 库存 | 按商品查询现有库存及库存流水；库存不得通过普通编辑修改。 |
| 分析与首页 | 销售、进货、库存统计；首页展示今日/本周/本月销售单数、销售额、销售毛利及上月同期展示，并提供销售开单、商品列表、进货、客户、价格查询、库存查询快捷入口。 |

### 2.2 后续可选或预留

- 手机号注册、登录及短信服务配置。
- 局域网多机访问。

### 2.3 明确不作为首期功能

- 仓库管理、盘点、调拨、库存预警、批次、序列号、保质期。
- 财务总账、线上商城、复杂审批流、移动端。

## 3. 用户与权限

| 角色 | 范围 | 权限 |
| --- | --- | --- |
| boss | 自己创建的独立数据空间 | 不受功能权限限制；创建 employee；授予、审批 employee 权限；维护本组织业务数据。 |
| employee | 唯一所属 boss 的数据空间 | 默认销售开单、进货开单和查询权限；其余模块操作仅在 boss 授权后可用。不得自助注册。 |

前端应隐藏无权入口；后端必须按当前账号归属的 boss 过滤对象并拒绝越权请求。

## 4. 术语

| 术语 | 定义 |
| --- | --- |
| boss | 可直接注册、拥有独立业务数据空间的老板账号。 |
| employee | 由 boss 创建、只可访问其所属数据空间的员工账号。 |
| 初始库存 | 商品首次建档时录入的库存，必须形成可追溯来源。 |
| 库存流水 | 记录初始库存、进货、销售及退货引起的商品库存增减的不可变记录。 |
| 价格等级 | 商品可维护的销售价格类别，默认包含零售价和批发价。 |

## 5. 功能需求

### 5.1 认证、员工、角色与店铺

- 新用户可用用户名和密码注册 boss；注册成功后可登录。
- boss 可新增 employee（用户名/姓名和密码）；employee 仅能以该账户登录，不能注册。
- boss 可在员工和角色权限中查看、授予权限，并处理 employee 的申请；employee 可发起申请并查看结果。
- boss 可查看、编辑本店铺信息；employee 的查看或编辑权限待确认。

### 5.2 基础资料

- 用户可在获授权范围内维护商品、规格、单位、属性、属性选项、价格等级、客户和供应商。
- 商品可关联规格、单位、属性、多个价格等级价格和一个可选默认供应商；商品新增时可填写初始库存。默认供应商仅供资料维护，不会自动代入采购单。
- 被业务单据引用的资料不得造成历史单据失真；具体删除与停用行为由领域规则约束。

### 5.3 单据与库存

| 流程 | 输入 | 输出/结果 |
| --- | --- | --- |
| 商品建档 | 商品资料、初始库存、价格 | 创建商品及初始库存来源记录。 |
| 进货 | 供应商、商品明细、数量及金额 | 受控完成后库存增加，保留进货与库存流水。 |
| 进货退货 | 供应商、商品明细、数量及金额 | 受控完成后库存减少，保留来源追溯。 |
| 销售 | 客户、商品明细、数量及金额 | 受控完成后库存减少，记录销售金额，统计可见。 |
| 销售退货 | 客户、商品明细、数量及金额 | 受控完成后库存增加，冲减销售金额。 |
| 库存查询 | 商品等筛选条件 | 显示当前库存与对应流水。 |

单据状态采用草稿和已完成：草稿可编辑，完成后不可编辑或删除；首期不提供作废或反审核，纠错通过新建相应退货单处理。销售完成时禁止负库存，库存不足则拒绝完成。数量保留四位小数，金额保留两位小数，行金额与单据总额由后端以四舍五入计算。

### 5.4 统计与首页

- 销售统计展示销售数据；进货统计展示进货数量和金额；库存统计展示所有商品当前库存相关数据。
- 首页从分析模块读取销售单数、销售额和销售毛利，并按今日、本周、本月及上月对比展示。
- 统计维度、时间边界与筛选条件待确认；毛利使用商品进货价在销售/销售退货完成时锁定的成本快照计算。

## 6. 核心流程

| ID | 流程 | 参与者 | 验收结果 |
| --- | --- | --- | --- |
| FR-01 | 注册与登录 | 新用户、boss、employee | 仅注册产生 boss；登录后身份及权限正确。 |
| FR-02 | 员工授权 | boss、employee | employee 申请可被所属 boss 审批；授权立即受后端约束。 |
| FR-03 | 商品建档 | 有商品维护权限者 | 商品资料、价格和初始库存完整保存，初始库存可追溯。 |
| FR-04 | 采购入库 | 有进货权限者 | 进货完成后库存增加且产生流水。 |
| FR-05 | 销售出库 | 有销售权限者 | 销售完成后库存减少且产生流水、销售统计更新。 |
| FR-06 | 采购退货 | 有进货退货权限者 | 完成后库存减少且可追溯退货来源。 |
| FR-07 | 销售退货 | 有销售退货权限者 | 完成后库存增加且冲减销售数据。 |
| FR-08 | 库存与统计查询 | 有查询权限者 | 仅看到本 boss 数据，余额、流水和统计一致。 |

## 7. 非功能需求

- 后端采用 Python、Django、Django REST Framework；前端采用 Vue 3、TypeScript、Vite、Element Plus、Pinia、Axios、TanStack Query for Vue；数据库为 PostgreSQL。
- API 使用 REST、JWT 和 drf-spectacular OpenAPI；前后端分离。开发机使用本机安装的 Python、Node.js 与 PostgreSQL，不安装 Docker；运行机使用 Docker Compose 以固定版本镜像构建并运行服务。
- 金额使用 `numeric` 与 `Decimal`，API 中金额和高精度数量以字符串表示，禁止浮点数。
- 库存、金额和单据状态变化必须在数据库事务中执行；后端必须保持库存流水审计与幂等性。
- 桌面浏览器为首要界面，常用办公屏幕为主要目标；必须防止跨 boss 数据访问。

## 8. 范围外内容

首期不得将仓库、盘点、调拨、预警、批次、序列号、保质期、税务、财务总账、线上商城、移动端或短信服务实现为既有能力。

## 9. 待确认事项

| ID | 缺口与影响 | 选项与建议 |
| --- | --- | --- |
| RQ-01 | 已确认：首期状态机为草稿、已完成；完成后通过退货单纠错，不实现作废或反审核。 | 后续如需作废/反审核，须先定义反向流水与审计规则。 |
| RQ-02 | 已确认：销售完成禁止负库存。 | 锁定库存余额后不足则返回库存不足冲突。 |
| RQ-03 | 商品、客户、供应商、店铺字段及 employee 可见店铺范围未定义。 | 确认最小字段和访问权限，避免把参考图字段当需求。 |
| RQ-04 | 已确认：数量为四位小数、金额为两位小数；首期不支持折扣、税额或含税口径。 | 后续税务或折扣需求须定义统一取整策略并迁移数据模型。 |
| RQ-05 | 价格等级数量上限已定义为六，但销售价格选择、客户默认等级和改价权限未定义。 | 确认定价选择规则及权限。 |
| RQ-06 | 已确认：商品维护进货价；销售与独立销售退货完成时按当时进货价锁定成本快照，毛利为净销售额减净销售成本。 | 后续如需先进先出、移动加权平均或退货关联原销售单，须定义迁移和历史重算规则。 |
| RQ-07 | 删除、停用、初始库存更正、退货是否需关联原单未定义。 | 确认审计与追溯策略；建议停用资料、初始库存只允许受控更正。 |
