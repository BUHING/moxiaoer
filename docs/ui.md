# 磨小二进销存系统界面规格

## 1. 导航与路由

| 一级菜单 | 页面/路由 | 权限 |
| --- | --- | --- |
| 首页 | `/dashboard` | 查询权限。 |
| 商品 | `/products`、`/products/specifications`、`/products/units`、`/products/attributes`、`/products/prices` | 查询或对应维护权限。 |
| 销售 | `/sales`、`/sales/new`、`/sales/returns` | 查询、销售开单或销售退货权限。 |
| 客户 | `/customers`、`/price-levels` | 查询或维护权限。 |
| 进货 | `/purchases`、`/purchases/new`、`/purchase-returns`、`/suppliers` | 查询、进货或进货退货权限。 |
| 库存 | `/inventory/balances`、`/inventory/movements` | 查询权限。 |
| 分析 | `/reports/sales`、`/reports/purchases`、`/reports/inventory` | 查询权限。 |
| 设置 | `/settings/employees`、`/settings/roles`、`/settings/shop` | boss 或已授权 employee。 |

未认证进入登录页；无权限使用 403 页面，不存在路由使用 404 页面。登录后默认首页。菜单和快捷入口仅展示当前用户可执行项，但 API 返回的 403 必须就地说明无权限。

## 2. 页面与交互

| 页面 | 数据/API | 主要内容与状态 |
| --- | --- | --- |
| 登录、注册 | `/auth/token/`、`/auth/register/` | 用户名、密码；注册文案明确仅创建 boss；字段错误显示在输入项旁。 |
| 首页 | `/dashboard/` | 今日/本周/本月及上月销售单数、销售额、毛利；六项快捷入口。 |
| 商品及资料列表 | 对应基础资料 API | 搜索、启用状态筛选、分页、排序、创建、编辑、停用；供应商维护名称、联系人、联系人地址、电话与备注；列表显示进货价，加载骨架、空状态、可重试错误。 |
| 商品表单 | `/products/`、供应商/价格/单位/规格/属性 API | 名称、可选默认供应商、单位、进货价、规格、属性、销售价格、初始库存；价格和初始库存即时校验，库存仅新建可录入。默认供应商不自动覆盖采购单选择。 |
| 购销及退货列表 | 单据 API | 编号、伙伴、日期、金额、状态、完成时间；草稿可编辑并完成，完成单据只读。 |
| 单据编辑/详情 | 单据及库存 API | 基础信息、可扫描/检索商品明细、数量单价、后端金额汇总、状态时间线和库存影响；完成前弹出确认。 |
| 库存 | `/inventory/balances/`、`/inventory/movements/` | 商品库存表及可筛选、分页的只读流水。 |
| 统计 | `/reports/*` | 日期范围、已确认维度的数据表/汇总；统计口径未知项不虚构图表。 |
| 员工与角色 | `/employees/`、`/permission-requests/` | boss 创建员工、授予权限、审批申请；employee 发起并查看申请。 |
| 店铺 | `/shop-profile/` | 已确认字段的读取/编辑；employee 范围待确认。 |

## 3. 表单与状态规则

- 客户与供应商允许同名，按 MD-005~007 的组合身份判重。重复保存的中文提示显示在新增、编辑弹窗内，保持弹窗打开并保留已填内容；停用冲突明确说明“仅停用”筛选。不得再将预期的重复资料冲突显示为 `Internal Server Error`。
- 销售及销售退货的客户选项显示“名称｜联系人｜电话”；进货及进货退货、商品默认供应商选项显示“名称｜联系人｜联系地址｜电话”，未填写的可选信息明确标注。选项值、单据及商品关联仍为 UUID，不按名称合并或关联；同名资料列表分页以 ID 作为名称排序的次级顺序，避免跨页遗漏。开单中的快捷新增也提供相应可选联系字段，并在该弹窗内提示重复，失败不清空表单。
- 商品、客户、供应商列表在刷新按钮右侧提供六种排序：“名称顺着排（A → Z）”“名称倒着排（Z → A）”“最早添加的在前”“最新添加的在前”“最早修改的在前”“最近修改的在前”。默认“名称顺着排（A → Z）”；旁边展示提示：中文按拼音排列，数字按大小排列。按当前浏览器的登录用户、组织、页面分别保存选择，刷新、搜索、筛选和编辑后仍保持选择，存储失败时明确提示。仅调整显示文案，沿用原有排序值和存储键，已有选择无需重新设置。
- “名称顺着排”依次为数字开头、汉字开头、英文字母开头、其他符号开头；组内比较完整名称，汉字按标准拼音、英文主排序忽略大小写、数字按自然数值比较。“名称倒着排”整体反向；同值按名称及内部 ID 稳定排序。仅在排序比较时去除首尾空白并规范化全角字符，不修改原始资料。
- 三个资料列表自动取齐符合搜索和启用状态条件的所有分页数据，再对完整结果排序，不修改共享查询缓存或单据表单中的选择列表。未来改为服务端分页时，必须同步实现服务端全局排序。
- 最近修改时间为资料自身的 `updated_at`，包括编辑和停用；库存变动、开单不算修改资料。
- 销售、销售退货、进货、进货退货首次保存时显示后端生成的正式时间单号；未保存时仍显示“新建草稿”。单号列不随意折行，窄屏通过表格横向滚动查看；详情标题允许完整换行，原单选择显示完整单号。
- 金额与数量输入使用字符串高精度组件，显示精度在 MONEY-003 确认后统一；不得前端自行计算最终总额。
- 商品、伙伴和价格等级使用可搜索选择控件；停用资料不可用于新单据，历史详情保留快照。
- 草稿单据可编辑；完成后字段、明细和删除按钮不可用。完成按钮调用专用 `complete` 动作并禁用重复提交，错误按 API `code` 展示。
- 删除、停用、完成均需确认对话框；库存不足、状态冲突、权限拒绝使用可理解的错误反馈。

## 4. 统一规范

界面使用 Element Plus；API 状态由 TanStack Query for Vue 管理，认证及全局用户/权限由 Pinia 管理。OpenAPI 自动生成 TypeScript Client 和类型，页面不可维护重复 DTO。桌面优先适配至少 1366px 宽；扫码枪输入应聚焦商品搜索并支持回车选中。手机号、仓库、盘点、调拨、预警、导出及移动端页面不在首期。

## 5. 待确认事项

- 商品、客户、供应商、店铺的完整字段；销售价格选择和改价权限。
- 单据状态、作废/反审核、原单关联、负库存提示。
- 时间格式、金额/数量精度及统计分组。
