# 进销存项目 AI 提示词使用说明

`docs/功能模块设计.docx` 是本项目的初版功能设计稿和所有规格生成工作的主文档。它描述必须实现的功能、首期范围、业务流程及参考页面；其中的参考图只用于理解交互意图，不能覆盖文字说明，也不能据此臆造未描述的功能。

按下列顺序，将每个文件中的提示词完整复制给 AI。除第 10 步外，每一步都必须以功能模块设计为首要输入，并同时遵循已确认的上游 Markdown 文档。AI 生成的结果保存到项目对应的 `docs/` 文件中。

1. `01-生成需求规格提示词.md` -> `docs/requirements.md`
2. `02-生成领域规则提示词.md` -> `docs/domain-rules.md`
3. `03-生成数据模型提示词.md` -> `docs/data-model.md`
4. `04-生成API规范提示词.md` -> `docs/api.md`
5. `05-生成界面规格提示词.md` -> `docs/ui.md`
6. `06-生成验收测试提示词.md` -> `docs/acceptance.md`
7. `10-生成系统设计说明书提示词.md` -> `docs/system-design.md`
8. `07-生成项目README提示词.md` -> `README.md`
9. `09-初始化项目与目录说明提示词.md` -> 初始化项目并生成 `DIRECTORY_STRUCTURE.md`

`docs/system-design.md` 是基于功能模块设计和前六份已确认规格汇编、消除歧义后的最终系统设计说明书，包含概念设计、逻辑设计和数据库设计。代码初始化、模块开发和后续变更应优先以它为技术设计基线；若它与功能模块设计或上游规格冲突，必须回到源文档确认并同步修订，不能自行选择。

前六份是分领域规格，第七步将其收敛为最终系统设计说明书。系统设计说明书确认后，再让 AI 初始化并开发项目。每次开发新模块时，附上 `docs/功能模块设计.docx`、`docs/system-design.md` 及关联的规格文档，并要求 AI 严格遵循已有规则；有冲突时不得自行猜测或悄悄改变规则。

各提示词中的方括号内容可以在提交前替换。若功能模块设计、上游规格或方括号内容尚未确定，应在输出文档的“待确认事项”中列出影响、可选方案和建议，而不是擅自决定。
