# 生成 `docs/data-model.md` 的提示词

```text
你是一名 PostgreSQL 和 Django ORM 架构师。以 `docs/功能模块设计.docx` 为功能范围主文档，并根据 `docs/requirements.md` 与 `docs/domain-rules.md`，为进销存系统设计数据模型，并只输出将保存为 `docs/data-model.md` 的 Markdown 正文。不要输出 Django Model 代码、SQL migration 或前端代码。

## 主文档使用规则
- 只设计支撑主文档明确首期功能的实体、关系和字段；参考图不能作为字段或模块来源。
- 必须将主文档中的账号层级、数据隔离边界、商品规格/属性/价格等级、单据和统计口径转换为可追溯的模型设计。
- 主文档、需求规格和领域规则冲突或缺少建模所需信息时，不能擅自补全，应在“待确认事项”说明影响。

## 技术约束
- PostgreSQL 是唯一正式数据库，Django ORM 管理数据迁移。
- 货币和金额：PostgreSQL numeric；后端 Python Decimal；禁止 float。
- 所有主业务表需有创建时间、更新时间；需要审计的表需有创建人、更新人或操作人。
- 已有业务引用的基础资料不可物理删除，设计 is_active 或等价停用机制。
- 需要按业务规则支持事务、唯一性约束、审计追溯和并发控制。

## 至少分析和设计这些实体
- 账号主体/组织或等价租户边界、用户、角色/权限（尽量复用 Django 内置认证模型）、员工管理、店铺信息和操作日志（仅在主文档范围内设计）。
- 商品分类、计量单位、商品、规格、商品属性、属性选项、价格等级、商品价格、供应商、客户，以及主文档确认的其他基础资料。
- 采购单与采购明细、销售单与销售明细、采购退货与销售退货及其明细。
- 库存余额、库存流水，以及商品初始库存的合规来源。
- 盘点、调拨、仓库、预警等仅在主文档或上游规格确认时设计；若可统一单据模型，请解释取舍，避免为抽象而抽象。

## 输出要求
1. 先给出设计原则与命名约定：表/模型名、主键策略、时间字段时区、软删除/停用策略、金额和数量精度策略。
2. 给出实体关系总览。使用 Mermaid ER 图；同时提供文字关系说明，不能只依赖图。
3. 对每个实体用表格列出：字段名、建议 PostgreSQL/Django 类型、是否可空、默认值、含义、校验或约束。明确区分系统字段、业务字段、派生字段。
4. 列出外键关系、删除行为、唯一约束、Check 约束和必要索引；说明每个关键索引支撑的查询或一致性需求。
5. 明确库存余额与库存流水的关系：哪个是权威审计来源、哪个用于高效查询、如何保证一致，禁止让两者产生双写漂移。
6. 标记敏感字段、不可变字段及应由后端计算而非客户端提交的字段。
7. 定义关键枚举值及含义，包括单据状态、库存流水类型和方向。
8. 用“待确认事项”列出任何无法从输入文档确定的字段或建模选择，说明推荐方案和影响。

模型应支持后续生成 Django migrations、DRF serializers、OpenAPI Schema 和 Vue TypeScript 类型，但不要在本次输出中生成它们。
```
