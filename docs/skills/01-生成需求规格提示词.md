# 生成 `docs/requirements.md` 的提示词

```text
你是一名资深产品经理和企业软件业务分析师。请以 `docs/功能模块设计.docx` 为主文档，为一个单机优先、前后端分离的进销存 Web 系统编写完整的需求规格文档，并只输出 Markdown 正文。输出将原样保存为 `docs/requirements.md`，不要输出开发代码、实现方案或寒暄。

## 主文档使用规则
- `docs/功能模块设计.docx` 的文字描述是功能范围、首期边界、角色权限、业务流程和术语名称的首要依据。设计参考图仅用于理解交互意图，不能覆盖文字描述，也不能据此增加功能。
- 将主文档中的功能逐项转写为可验收需求；明确标出的“首期只实现”必须保留，未描述的功能不得因通用进销存惯例而补入首期。
- 主文档有矛盾、遗漏或无法判断的内容时，集中列入“待确认事项”，说明受影响模块和建议；不得自行确定业务规则。

## 已确定的技术与运行前提
- 后端：Python、Django、Django REST Framework。
- 前端：Vue 3、TypeScript、Vite、Element Plus、Pinia、Axios、TanStack Query for Vue。
- 数据库：PostgreSQL。
- 认证：JWT。
- API：REST API，使用 drf-spectacular 维护 OpenAPI。
- 开发机：Windows 本机安装 Python、Node.js 和 PostgreSQL，不安装 Docker。
- 运行机部署：Docker Compose；必须使用与开发机环境基线一致的固定版本基础镜像。主要在一台 Windows 电脑上通过浏览器使用，未来可选择局域网多机访问。
- 架构：单体后端 + 独立前端；不采用微服务。

## 需从主文档确认的产品背景
- 产品名称、目标组织与行业、初始用户规模。
- 账号体系、数据隔离边界、首期角色及权限。
- 首期功能、后续预留功能和明确不做的内容。
- 货币、税务、仓库、批次、序列号、保质期等业务范围。

## 首期范围提取要求
按主文档的模块顺序完整列出首期必须实现的功能及其子功能，并区分：
1. 必须实现：主文档明确要求的登录注册、账号与权限、基础资料、业务单据、库存、统计分析等实际模块。
2. 后续可选或预留：主文档明确标为预留、后续开通或后续实现的能力。
3. 明确不做或尚未确认：主文档未覆盖且会影响范围的常见进销存能力。

## 文档要求
- 用“目标、范围、用户与权限、术语、功能需求、核心流程、非功能需求、范围外内容、待确认事项”的章节组织。
- 对每个模块列出用户可执行的操作、输入、输出、业务结果和权限要求。
- 用表格写出主文档定义的全部核心业务流程；采购入库、销售出库、采购退货、销售退货等已描述流程必须覆盖。盘点、调拨等未纳入首期的流程只能列为待确认或后续范围。
- 区分“首期必须实现”“后续可选”“明确不做”。
- 不要把数据库字段、API 路径和具体页面组件当作需求；它们由后续文档定义。
- 未提供的信息不要自行编造。集中写入“待确认事项”，说明其会影响的业务和推荐选项。
- 确保需求能被拆分为独立开发任务和可验收功能。
```
