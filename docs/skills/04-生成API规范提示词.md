# 生成 `docs/api.md` 的提示词

```text
你是一名 REST API 架构师。以 `docs/功能模块设计.docx` 为功能范围主文档，依据 `docs/requirements.md`、`docs/domain-rules.md` 和 `docs/data-model.md`，为该进销存系统编写 API 规范 `docs/api.md`。只输出 Markdown 正文；不要实现代码。API 将由 Django REST Framework 与 drf-spectacular 实现，并生成 OpenAPI 文档。

## 主文档使用规则
- 仅为主文档明确的首期模块和上游规格已确认的支撑能力定义端点；参考图不构成 API 功能清单。
- 必须体现主文档要求的账号层级、数据隔离、员工授权和模块权限。主文档与上游规格出现冲突或缺少接口行为时，列入“待确认事项”，不得固化猜测。

## 固定约束
- API 根路径为 /api/v1/。
- 前端为 Vue 3 + TypeScript，API 契约必须稳定、可生成类型。
- JWT 用于认证；请求必须说明所需权限。
- JSON 使用 lower_snake_case 字段名。
- 金额和高精度数量在 JSON 中用字符串传输，例如 "12.50"，不得使用浮点数。
- 所有写库存、审核、作废、反审核等关键操作必须由专用动作接口表达，不能通过普通 PATCH 偷偷改变状态或库存。
- 不直接暴露 Django 内部字段和无权限数据。

## 要求覆盖的 API
- 认证和当前用户：登录、刷新 Token、获取当前用户和权限。
- 账号、员工、角色权限、店铺信息，以及主文档确认的认证和授权流程。
- 基础资料：商品分类、规格、单位、商品属性、价格等级、商品价格、供应商、客户，以及主文档确认的其他资料。
- 采购、销售、采购退货、销售退货、库存查询、库存流水和统计分析。
- 盘点、调拨、库存预警、Excel 导出、备份等仅在主文档或上游规格明确纳入范围时覆盖。

## 文档要求
1. 定义通用约定：认证 Header、时区/日期格式、金额格式、分页、排序、筛选、搜索、幂等键（若需要）、请求追踪 ID。
2. 定义统一响应和错误格式，至少包括参数校验失败、未认证、无权限、资源不存在、状态冲突、库存不足、并发冲突、服务异常。
3. 按模块列出每个端点：HTTP 方法、路径、用途、权限、查询参数、请求体、成功响应、错误响应、涉及的领域规则编号。
4. 对主文档范围内的采购入库、销售出库、退货、审核/作废等关键动作给出完整示例请求与响应，并明确幂等和重复操作的结果；盘点、调拨等仅在已确认范围内示例化。
5. 明确客户端不能提交、只能由后端计算或读取的字段，例如单据总额、库存余额、审核人、审核时间、库存流水。
6. 列出列表接口的筛选、排序和分页字段，避免前端依赖未定义行为。
7. 给出 API 版本兼容策略，以及字段新增、废弃和枚举扩展的规则。

如果输入文档对接口行为没有定义，不能猜测并固化为规范；请在“待确认事项”列出缺口及推荐选项。
```
