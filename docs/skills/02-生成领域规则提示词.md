# 生成 `docs/domain-rules.md` 的提示词

```text
你是一名熟悉零售、批发和仓储业务的领域架构师。以 `docs/功能模块设计.docx` 为功能范围主文档，并根据已确认的 `docs/requirements.md`，为进销存 Web 系统编写 `docs/domain-rules.md`。只输出 Markdown 正文；不要写代码，不要重复需求文档的通用描述。

## 主文档使用规则
- 主文档的文字描述决定首期功能、账号模型、数据隔离、角色权限和业务动作；`docs/requirements.md` 应是其可验收转写。两者冲突时不得自行裁决，记录待确认事项。
- 只为主文档明确的首期业务动作制定可执行规则。盘点、调拨、预警、批次等未明确纳入首期的能力，不得写成必须实现；可说明其缺失会影响的规则并列为待确认事项。

## 固定技术前提
- Django + Django REST Framework + PostgreSQL。
- 前后端分离，所有最终业务规则由后端执行。
- 金额在 PostgreSQL 使用 numeric、Python 使用 Decimal；禁止 float。
- 所有会改变库存、金额或单据状态的操作必须在数据库事务中完成。

## 强制领域原则
1. 库存不能被任意接口或页面直接修改。
2. 每次库存增减必须创建一条不可随意篡改的库存流水，并能追溯来源单据、操作人和时间。
3. 主文档纳入范围的采购入库、销售出库、采购退货、销售退货及其他库存变动，必须使用明确的业务动作和库存方向。
4. 已审核或已完成的单据不能直接编辑或删除；纠错应通过作废、反审核或反向业务单据完成。请基于需求选择精确策略并说明。
5. 所有单据状态转换必须幂等，重复请求不得重复扣减或增加库存。
6. 商品、仓库、供应商、客户等已有业务引用的基础资料，禁止物理删除；定义停用策略。
7. 权限必须同时由前端控制展示、后端强制校验。

## 需要在文档中明确的内容
- 术语与口径：可用库存、库存余额、库存流水、在途库存、锁定库存（若首期不支持也要写清）、成本、含税/未税金额。
- 主文档范围内所有单据类型的状态机：状态、允许的转换、触发者、前置条件、库存/金额影响、失败结果。
- 库存流水标准：流水方向、数量正负号口径、来源类型、来源编号、仓库、商品、发生时间、操作人、备注。
- 各已纳入首期的业务动作的精确规则：采购入库、采购退货、销售出库、销售退货、单据作废或反审核必须覆盖；盘点盈亏、调拨出库/入库仅在主文档确认后覆盖。
- 库存不足和负库存：根据 requirements.md 决定；若未确定，给出“禁止负库存”和“允许负库存”两种影响及推荐，不得私自选定。
- 单据编号、时间、数量精度、金额精度、折扣、税额和总额的计算及取整口径。
- 并发安全：同一商品和仓库被同时出库时的处理原则，以及为什么必须在数据库事务和锁机制中实现。
- 按主文档定义的账号与授权关系，明确创建、编辑、审核、作废、查看成本、导出数据等权限边界，以及数据隔离规则。
- 每条不可违反的规则标明唯一规则编号，如 INV-001、DOC-001、MONEY-001，供 API、测试和开发任务引用。

## 输出结构
使用“总则、术语与口径、库存规则、单据状态机、金额规则、基础资料规则、权限规则、并发与一致性规则、审计与追溯、待确认事项”。尽量使用决策表和状态转换表，写成开发人员能够直接执行、测试人员能据此编写用例的规则。
```
