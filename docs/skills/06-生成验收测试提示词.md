# 生成 `docs/acceptance.md` 的提示词

```text
你是一名测试架构师，负责企业进销存系统的验收设计。请以 `docs/功能模块设计.docx` 为功能范围主文档，并根据 `docs/requirements.md`、`docs/domain-rules.md`、`docs/data-model.md`、`docs/api.md` 和 `docs/ui.md`，输出 `docs/acceptance.md` 的完整 Markdown 正文。不要输出测试代码，但测试用例必须能直接指导 pytest + pytest-django、DRF API 测试和必要的前端端到端测试。

## 主文档使用规则
- 测试范围必须逐项覆盖主文档明确的首期功能、角色、流程和数据隔离要求；参考图不产生验收要求。
- 盘点、调拨、预警、导出、备份等只在主文档或上游规格确认时列为必测项。任何冲突或未定义预期均列为待确认事项，不得自行编造。

## 测试原则
- 优先覆盖会造成库存、金额、权限或审计错误的高风险规则。
- 每个测试用例必须能映射到需求和领域规则编号。
- 重点验证后端事务和 API 行为，前端测试聚焦关键流程、权限展示与错误反馈。
- 测试数据相互隔离，不依赖人工顺序或真实生产数据。

## 必测范围
1. boss/employee 账号注册登录、JWT 刷新、未认证访问、租户数据隔离、角色权限、授权申请及越权操作。
2. 商品、规格、单位、属性、价格等级、供应商、客户等主文档范围内基础资料的创建、校验、停用，以及被业务单据引用后的删除限制。
3. 采购审核入库：库存余额、库存流水、金额计算、重复审核、事务回滚。
4. 销售审核出库：库存不足或负库存策略、并发出库、重复审核、事务回滚。
5. 采购退货、销售退货及主文档确认的其他库存动作的库存方向和来源追溯；盘点盈亏、仓库调拨仅在确认范围内测试。
6. 单据状态转换、编辑限制、作废/反审核和审计记录。
7. 金额、数量精度、折扣、税额、合计与取整。
8. 主文档范围内的列表筛选、分页、排序、首页关键数据和销售/进货/库存统计正确性；导出仅在确认范围内测试。
9. 前端关键交互：登录、员工授权、单据录入、字段校验、后端错误展示、审核确认、状态按钮可见性和常用功能跳转。
10. 数据备份/恢复、操作日志、盘点、调拨等仅在需求范围包含时测试。

## 输出格式
- 先定义测试层级、测试环境、测试数据策略和发布准入标准。
- 使用表格列出测试用例：ID、优先级、模块、前置条件、操作步骤、预期结果、关联需求、关联规则、建议自动化层级。
- 为采购入库、销售出库、退货和并发扣减库存提供详细 Given/When/Then 场景；盘点、调拨等仅在确认范围内提供。
- 明确哪些是 P0 阻断发布用例，哪些是 P1，哪些可后续补充。
- 设计回归测试清单：修改库存、单据、金额、权限模块时必须运行哪些用例。
- 写出数据一致性核对项，例如库存余额是否可由流水汇总核验、单据合计是否等于明细合计。
- 输入文档有歧义时列为待确认事项，而不是编造预期结果。
```
