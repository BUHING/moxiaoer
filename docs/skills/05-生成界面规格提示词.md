# 生成 `docs/ui.md` 的提示词

```text
你是一名企业后台产品设计师和 Vue 3 前端架构师。请以 `docs/功能模块设计.docx` 为功能范围和参考交互主文档，依据 `docs/requirements.md`、`docs/domain-rules.md` 与 `docs/api.md`，为进销存系统编写 `docs/ui.md`。只输出 Markdown 正文，不要生成 Vue 组件代码、CSS 或图片。

## 主文档使用规则
- 主文档的文字决定页面、功能和首期范围；其中参考图仅用于理解信息层级和操作意图，不要求复刻，也不能据此增加未描述功能。
- 仅为主文档或上游规格明确的首期功能设计页面。移动端、盘点、调拨、预警、导出等未确认范围不能默认纳入。
- 账号隔离、员工默认权限、授权申请和店铺信息等交互必须以主文档为准；有冲突或缺失时列入“待确认事项”。

## 固定前端技术栈
- Vue 3 + TypeScript + Vite。
- Element Plus 作为后台 UI 组件库。
- Pinia 管理认证态、用户信息和必要全局字典。
- Axios + TanStack Query for Vue 管理 API 请求、缓存、加载与错误状态。
- 使用 OpenAPI 自动生成 TypeScript 类型和 API Client；不得手工复制后端 DTO。

## 页面范围
- 登录页、无权限/未找到页面。
- 首页仪表盘。
- 商品：商品、规格管理、单位管理、商品属性、价格管理。
- 销售及销售退货、进货及进货退货的列表、新建/编辑和详情。
- 客户、价格等级、供应商、库存查询及库存流水。
- 销售、进货、库存统计和首页关键数据展示。
- 员工管理、角色权限、店铺信息，以及主文档确认的设置功能。
- 仓库、盘点、调拨、预警、导出、操作日志等仅在已确认范围内设计。

## 输出要求
1. 定义总体导航信息架构：一级菜单、二级菜单、路由、所需权限、默认落地页。
2. 对每一页说明：目标用户、访问权限、数据来源 API、筛选项、表格列、分页/排序、主要按钮、批量操作、空状态、加载状态、错误状态。
3. 对每个新增/编辑表单说明：字段、组件类型、必填规则、前端即时校验、后端校验错误的呈现方式、只读条件。
4. 对单据详情页定义：基础信息、明细表、金额汇总、状态时间线、库存影响摘要、可执行动作及动作确认对话框。
5. 明确状态驱动的交互：草稿、已审核、已作废等不同状态下哪些操作和字段可用；前端展示仅改善体验，最终以后端权限与规则为准。
6. 定义统一交互规范：日期与金额格式、数量精度、成功/失败提示、删除确认、危险操作确认、导出下载、权限缺失处理。
7. 为扫码枪输入、桌面浏览器和 1366px 宽度以上的常见办公屏幕给出合理的交互要求；无明确需求时不要过度设计移动端。
8. 每个页面或表单都引用对应 API 路径和领域规则编号，确保开发人员不需猜测。
9. 在文末列出待确认事项和低保真界面决策，禁止自行虚构品牌视觉规范。
```
