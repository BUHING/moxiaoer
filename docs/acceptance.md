# 磨小二进销存系统验收测试

## 1. 测试策略与准入

使用 pytest、pytest-django 和 DRF API 测试验证服务、事务和权限；关键登录、员工授权、单据录入及错误反馈使用前端端到端测试。每例独立创建组织和数据。开发机使用本机 PostgreSQL，运行机使用 Compose 中同版本 PostgreSQL 镜像。发布前所有 P0 通过，且库存余额可由流水汇总核验；未确认规则不得以猜测用例阻塞或放行。

## 3. Given/When/Then 场景

**采购入库**：Given 商品余额为 5，When 以唯一幂等键完成数量 3 的采购草稿，Then 余额为 8、创建 `PURCHASE +3` 流水；重试请求仍为 8。

**销售出库**：Given 商品余额为 8，When 完成数量 2 的销售草稿，Then 余额为 6、创建 `SALE -2` 流水并纳入销售统计。库存不足时预期须在 RQ-02 确认后固化。

**退货**：Given 已建商品，When 完成数量 1 的采购退货和销售退货，Then 分别生成负、正库存流水；原单关联要求须在 RQ-07 确认后测试。

## 4. 回归与一致性核对

变更库存、单据、金额或权限时，必须运行 AT-01、AT-02、AT-05 至 AT-12；UI 改动运行 AT-13；调整 Dockerfile、Compose、基础镜像或锁文件时运行 AT-14。核对每个 `(organization, product)` 的余额等于流水 `quantity_delta` 汇总，单据总额等于行金额汇总，所有单据/流水/资料查询均被组织过滤。状态、精度、负库存、成本与作废确认后补充对应 P0 用例。
